# SPEC - agent-team-harness (build contract, 2026-10-22)

The contract every builder works to. If code and this file disagree, this file wins until it is changed here.

## What this repo is

A skeleton for a team that shares ONE Claude Code agent persona and ONE memory, each member running Claude Code in
their own clone on **Linux**. Memory travels through git. Nothing from any individual's personal setup is in here.

Runtime requirements: **Python 3.10+ (stdlib only), Node 18+ (built-ins only), git, bash, Claude Code.** No pip, no
npm, no vendored binaries, no network calls. Blender is optional and only re-renders Insight art.

## Layout

```

README.md                      setup + onboarding
docs/ARCHITECTURE.md           how memory works (team version)

  SOUL.md                      principles
  TEAM.md                      the team: members, roles, how the team directs the agent
  PROJECTS.md                  pointers to where truth lives (never detail)
  ROUTING.md                   recall routes: request words -> skill / memory / doc to load

  lessons/<slug>.md            one lesson per file: type lesson + a trigger question
  log/YYYY-MM/YYYY-MM-DD.<member>.md   daily log, one file per member per day (never merge-conflicts)
  _gen/                        GENERATED, gitignored, rebuilt at session start by tools/memory_index.py
    INDEX.md                   grouped index of topics + lessons
    TRIGGERS.md                every active lesson's trigger question (tier 0)
agents-src/                    role agent sources (CORE-AGENTS.md, _role-common.md, <role>.src.md)

  hooks/                       hook scripts (python3 + one bash loader)
```

## Member identity

`member` = env `AGENT_MEMBER`, else `git config user.name`, else `$USER`; slugged to `[a-z0-9-]`, max 32 chars.
One function, `tools/common.py: member()`, used by every tool and hook. Never an email address.

## Memory frontmatter (the schema; tools/memory_lint.py enforces it)

```yaml
---
name: <kebab-case slug, equals the file name without .md>
description: <one line, the recall signal, <= 300 chars>
metadata:
  type: rule | decision | project | reference | lesson | runbook
  tags: [a, b]                  # lowercase kebab, >= 1
  status: active | superseded | ephemeral
  author: <member>
  created: YYYY-MM-DD
  verified: YYYY-MM-DD          # optional; last time someone checked it against reality
  superseded_by: <slug>         # required iff status: superseded
  trigger: "<question?>"        # required iff type: lesson; one line ending in '?'
  tier0: true|false             # lessons only; default true; false keeps it out of TRIGGERS.md
---
<body>. Link others with [[slug]].
```

Rules: `ephemeral` is flagged stale 14 days after `verified` (else `created`). `superseded` is kept, listed first
in the index under "do NOT act on", never deleted. Unknown keys are a lint WARNING, not an error. Parsing is a small
hand-written YAML subset (scalars, quoted strings, inline lists, one level of `metadata:`) - no PyYAML.

## Generated files (never hand-edit; gitignored)

`tools/memory_index.py` writes `memory/_gen/INDEX.md` and `memory/_gen/TRIGGERS.md` atomically (temp file +
os.replace) and refuses to write an empty index when memory/ has files (LESSONS-style guard: an empty input must
not overwrite). Exit 0 on success, prints one line with counts. It runs from the SessionStart hook before the
persona loader, so every member always sees an index of what is on their checkout.

INDEX.md groups: superseded (first), ephemeral-and-stale, rules, decisions, lessons, everything else; one line per
memory: `- [slug](../topics/slug.md) \`tags\` - description (truncated 120)`. Capped at 24 KB; over the cap it keeps
the superseded + rules groups whole and truncates the tail with a line saying how many were cut.

TRIGGERS.md: `- **"<trigger>"** ([[slug]])` per active lesson with tier0 true, newest `created` first, capped 12 KB
with the same truncation notice.

## Tier 0 (the SessionStart payload)

`.claude/hooks/load-persona.sh K N` emits part K of N (N = 8 in settings.json). Sections in order: IDENTITY (first,
so it is what survives any truncation; it carries the non-negotiables), SOUL, TEAM, TRIGGERS (memory_index.py
--print triggers), PROJECTS, ROUTING, SESSION (member id, daily-log path, the member's optional local
`~/.config/agent-team-harness/me.md` capped at 3 KB, the not-initialised banner), MEMORY INDEX (memory_index.py --print
index). Packed by `.claude/hooks/tier0-pack.py` into parts <= 9,000 bytes (the harness caps one hook's output at
10,000 characters and shows only a 2,000-character preview beyond that). Lines longer than a chunk are hard-split on
a UTF-8 boundary; part 1's reserve grows until its header + manifest fit. Part 1 carries the manifest, an OVERFLOW
banner (more parts needed than hooks) and an OVER CAP banner (a part over 9,000 bytes).
`load-persona.sh check N` prints the size table and exits 1 if it does not fit.

## Tool CLIs (all python3, stdlib, argparse; `--help` prints help, exits 0 and runs nothing)

Every code below is from the Exit codes table that follows; 64 (usage) applies to every tool and is not repeated.

| Tool | Does | Exit |
|---|---|---|
| `tools/common.py member` / `root` / `tier0-parts [--root DIR]` | shared values for the shell hooks: member id, repo root, N from the `load-persona.sh K N` SessionStart hooks (default 8 when none are found; exit 2 for a `--root` outside the repo) | 0 |
| `tools/memory_index.py` | regenerate _gen/ | 0 ok, 1 written but lint errors present, 2 refused (missing memory dir; empty input over a real index) |
| `tools/memory_index.py --check` | compare _gen/ with a fresh render; writes nothing | 0 fresh, 1 stale, 2 missing memory dir |
| `tools/memory_index.py --print index\|triggers\|lessons-json` | the bytes INDEX.md / TRIGGERS.md would hold, or every lesson as JSON (`{"lessons": [{name, description, trigger, created, status, tier0, tags, errors, file}]}`, newest first, tier0 a bool, errors [] when valid); writes nothing; on failure a placeholder (`(index unavailable: <Class>)` / `{"lessons": [], "error": "<Class>"}`) | 0 always |
| `tools/memory_lint.py` | validate every memory's frontmatter; never writes. ERROR also for a symlink or a name with a control character anywhere under memory/, and for a topic/lesson file name that is not `[a-z0-9][a-z0-9-]{0,63}.md` (never opened). WARNING `SUSPECT` for a description/trigger shaped like a command or an instruction (URL, curl/wget, pipe into a shell, backticks, `$(`, "ignore previous", "system prompt", "instructions", "disregard") | 0 clean (warnings allowed), 1 errors, 2 missing memory dir |
| `tools/memory_verify.py [--quick]` | health check, 13 checks: lint, index fresh (via `memory_index.py --check`: stale = WARN, any other failure = FAIL), tier0 fits, generated agents match sources, leak scan (WARN without a local name list), gitignore both ways (must-ignore AND must-commit), no file over 64 KB in memory/ (memory/_gen excluded, lstat), hooks exist and compile, persona initialised, org policy not disabling hooks, 11 no control character in any path git would commit or any name under memory/ and agent/, 12 no symlink under memory/, agent/, .claude/agent-memory/ (on disk or git mode 120000), 13 SUSPECT text (WARN only) | 0 no FAIL, 1 any FAIL; prints PASS/WARN/FAIL per check |
| `tools/memory_tools.py search "<q>"` | ranked BM25 over memory/** + agent/** + skills; never opens a symlink or an unsafe name | 0, 2 query has no searchable words |
| `tools/memory_tools.py dupes` / `stale` / `tier0` | near-duplicate pairs / stale ephemerals / tier-0 budget (advisory: `load-persona.sh check N`, N from common.tier0_parts) | 0 |
| `tools/agent_gen.py <role>... \| --all \| --check [role]` | build .claude/agents/<role>.md from agents-src; lessons through memory_lint, keyed by FILE slug (never `name:`), only error-free active lessons, description and trigger flattened to one line; honours AGENT_MEMORY_DIR; every role is processed even when one is refused | 0 ok, 1 drift (--check), 2 a role refused (incl. an invalid or unreadable lesson carrying its tag, named) |
| `tools/init_agent.py` | fill the persona templates (agent name, team name); prompts only on a real terminal and never with --dry-run | 0, 2 already initialised / no agent/*.md / a symlink in agent/ / bad value, 64 also when --name or --team is missing and there is no terminal to ask |
| `tools/leak_scan.py [--root DIR] [--path SUBDIR] [--list]` | fail on any string in tools/leak_patterns.txt (gitignored local list) plus built-in generic patterns (home paths `/home/<x>`, `C:\Users\`, emails, tokens). A line over 4096 chars is one "long line - unscanned" finding, a file over 512 KB one "unscanned" finding (no regex runs on either) | 0 clean, 1 findings |

**Paths outside the repo (every tool):** `--root`, `--memory-dir` and `--path` must resolve (realpath, so a symlink
cannot smuggle them out) inside the repo the tool lives in; otherwise exit 2, "outside the repo; set
AGENT_TOOLS_ANY_ROOT=1 to allow" (`--print` modes give the `OutsideRepo` placeholder instead). The tools are
allowlisted to run without a prompt, so a flag must not turn them into a reader of `~/anything`. Env
`AGENT_MEMORY_DIR` is not checked: setting env is not something a prompt-free tool call can do.

**Untrusted names:** every name and message a tool prints has its control characters escaped
(`common.printable`); an unsafe name is shown as its `repr()`, at most 80 chars (`common.shown`).

## Exit codes (every tool in tools/)

| Code | Meaning | Examples |
|---|---|---|
| 0 | ok | written, clean, fresh, in sync |
| 1 | findings: drift, lint errors, stale, leaks, a FAIL check | `memory_lint` errors, `agent_gen --check` drift, `memory_index` wrote but lint errors present |
| 2 | refused: the tool would destroy data, is already done, or refuses the input | empty input over a real index, missing memory dir, `init_agent` already initialised or a bad value, a search with no searchable words, an `agent_gen` role that cannot be built, a path flag outside the repo |
| 64 | usage error (EX_USAGE): bad flag, missing argument, bad `--today` | `--no-such-flag`, `memory_tools.py` with no subcommand, `agent_gen.py` with no role |

Rules: argparse everywhere through `common.ArgParser` (its `error()` exits 64, so argparse's own 2 never collides with
"refused"). Every error goes to stderr through `common.die(msg, code)`; stdout carries only results, so callers can
parse it. A usage error is detected before anything is read or written. `--print` is the one exception to all of it:
it always exits 0 and prints a placeholder instead of an error, because the tier-0 loader must never be blanked.
Unhandled exceptions exit 1 (Python's default), which is why memory_verify treats only the indexer's own "STALE"
verdict as stale and any other non-zero exit as FAIL.

## Hooks (settings.json, every command via "$CLAUDE_PROJECT_DIR")

SessionStart: load-persona.sh 1..8 (each computes the index in-process via memory_index.py --print), then memory_index.py writes _gen/ for tools and humans. UserPromptSubmit: librarian-gate check, skills-gate check.
PostToolUse: librarian-gate mark (Agent), skills-gate mark. Stop: librarian-gate stop, skills-gate stop.
PreToolUse: git-guard (Bash), heredoc-guard (Bash), stamp-guard (Write|Edit), agent-model-guard (Agent).
SessionEnd + PreCompact: session-log. SubagentStart: subagent-core. TaskCompleted + TeammateIdle: team-event-log.
State: `$CLAUDE_PROJECT_DIR/.claude/state/`. Every hook fails OPEN on its own errors and logs them there.

## Insight (local dashboard)

Scope: transcript parser, cost, alerts (on screen only), team graph, agent and lesson detail, memory-tier panel, the
Blender-rendered art + its script. Out of scope by design: any audio, any outbound call (no usage or account
endpoints, never reads Claude Code credentials), any endpoint that writes to disk, and spawning Claude. Security:
per-launch token on /api/*, Host allow-list, cross-site refusal on /api/*, `public + sep` static guard, malformed
escapes refused (400), CSP + frame/sniff/referrer headers, execFile for the browser, bind 127.0.0.1 only. Its lessons
panel reads memory/lessons/*.md; its tier panel reads `load-persona.sh check N` with N from settings.json.

## Harness facts this design rests on (docs checked 2026-10-22, code.claude.com/docs/en/...)

- `$CLAUDE_PROJECT_DIR` is exported to every hook process (hooks.md). Org managed settings `allowManagedHooksOnly` /
  `disableAllHooks` switch ALL project hooks off - memory_verify reports when tier 0 did not load for that reason.
- Hook output cap is 10,000 **characters** (hooks.md); the packer measures bytes (>= chars), so 9,000 bytes is safe.
- Auto memory (`~/.claude/projects/<slug>/memory/`) is per-user and machine-local. It stays ON, because "if auto memory
  is turned off, the `memory` field [of a subagent] has no effect" (sub-agents.md). Rule in CLAUDE.md: team knowledge
  goes to `memory/` via /wrap; auto memory is only for one member's private working notes.
- Role agents use `memory: project` -> `.claude/agent-memory/<role>/` (committed, shared by the team).
- Agent teams: experimental, one team per lead session, no cross-user channel; cross-session messaging covers only
  your own sessions (agent-teams.md, cross-session-messaging.md). Members coordinate through git.

## Not in scope

Cross-member live messaging (agent teams run inside one lead session; members coordinate through git). Any
personal memory, skill, lesson or tool from the author's own setup.
